## Decision

The 3.61 bindings were sufficient; no contradictory frozen contract was found.
Implement the official native fixture constructor, private lifetime, real
FilmSkillRepository/SodiumVerifier.loadTrusted path, and a test-only first-read
controlled port in the existing studio_demo App. Do not import Web test
libraries, invent an editor/art-page API, or claim File/GTK/OS AT qualification
from the test reader. Keep default construction on disabled policy, empty
grants, and unknown clock. Seed/root/time remain compiled test-entrypoint
inputs, never environment enrollment.

Independently qualify NG0–NG3 in this increment and stop before the seven
N01–N02 profiles. Those profiles still require actual GTK keyboard/semantics
flows, fixture navigation/disposal, held-read retirement, and continuous
no-write observation through each case. Landing a constructor hook together
with incomplete profile evidence would not be a coherent accepted slice.

## Recorded outcome

- NG0: actual-host anchors, one first-frame policy derivation, unchanged
  main/openDemo ownership, and frozen shared core/license trees.
- NG1: three fresh Linux release artifacts (default, ordinary opt-in, fixture
  entrypoint) with distinct libapp.so payloads; compiled public-key,
  fingerprint, and fixture-path sentinels are fixture-only.
- NG2: four lifetime unit tests, five controlled-reader tests (actual
  guard/selected/original future, cancel-null while busy, watchdog, immutable
  snapshots), and an xdotool Tab/Return canary on an actual Flutter Linux
  window. The canary is transport evidence, not N01.
- NG3: Directory.watch create/write/restore/rename/delete canary; reviewed
  strace 6.13 installation and loopback file/network canary; default and
  opt-in --smoke-test syscall allowlists recorded. No remote connect was
  observed. This is not N01–N02 no-write acceptance.
