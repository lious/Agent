# ADR 0088 — Official persist path for caption-aware SlipClip

## Status

Accepted for Increment 1.81 as a bounded slice of the original I-006 remaining work (s3 slip row). I-005 and I-006 remain partial. This increment does not claim I-006 complete (roll/slide and 1000 random legal I-006 inputs remain) and does not officialize field-aware invert of Slip, a complete invert matrix, mid-span insert-paste invert, or invert of a non-trailing leave-gap delete / LiftClips / ripple-delete. Official InversePatch `kind` stays `restoreSnapshot`. Linear undo/redo stay tip snapshot restores. The command remains `SlipClip(clipId, sourceDelta)`; this slice does not add `includeLinks`. Linked AV already slips link-group members together by the same source delta on the no-caption persistent-audio path, and that default include-links behavior is kept. Already-delivered invert semantics through Increment 1.80 stay unchanged. The Increment 1.73 and 1.78 invert version bumps and the Increment 1.79 invert-path gap insertion stay unchanged: in-place field restores run first, then a missing track gap is inserted by timeline start; media clips still append, so invert of a non-trailing leave-gap delete, LiftClips, or mid-span insert paste still refuses `IMPLICIT_GAP`. The single-clip Move button stays `MoveClip` and must not silently become Slip. Captions still do not enter the internal clipboard package. The OS clipboard stays closed. Video and caption mute/solo stay refused at admission with `FEATURE_NOT_IMPLEMENTED`; audio muted/solo stay `SetAudioTrackState`; `syncLock` is not toggled. Captions and markers are not burned into preview or MP4; export stays a VTT sidecar. Marker sidecar implementation is not in this checkout. This slice does not open RollCut, SlideClip, auto-close as a MoveClips mode, new-track, cross-project bake, source-interval crop, or pointer-drag Slip as a new gesture mode. A topology edit of a dissolve host remains `TRANSITION_RANGE_EDIT_REQUIRES_REMOVAL`. Slip remains allowed if transition handles revalidate. Uncovering or cropping a source-anchored cue remains whole-group `ANCHOR_OUT_OF_RANGE` and is never silently converted to absolute or cropped. Leaf-level rational `n`/`d` granularity is unchanged. Production edit algebra of already-delivered commands, insertion order, and `IMPLICIT_GAP` are unchanged.

## Context

Domain algebra for `SlipClip` and some no-caption tests already existed: `sourceRange.start` moves by `sourceDelta`; `timelineRange`, TimeMap shape, and sequence duration stay unchanged. The original 104-spec s3 slip row already specified those geometry rules, plus that source-anchored detection/captions reproject while clipLocal captions do not move, and that source head/tail and transition handles are validated. Until this increment, `applyEdit` and persistent-audio dispatch refused `SlipClip` with `CAPTION_SYNC_EDIT_NOT_IMPLEMENTED` whenever the project had captions (the allowlist was only `AppendVideoAsset`, `SplitClip`, `TrimClip`, `DeleteClip`, and `MoveClip`). The workbench had no official Slip control.

After a 1s split of a 3s clip, the left remnant source is `[0, 1)` and still has unused later source, so a legal positive slip of +15 source frames (`Q.of(1, 2)` on the 30fps grid, the s3 example delta) yields source `[1/2, 3/2)` while the timeline range stays `[0, 1)`. The right remnant already uses source through the stream end, so a positive slip of that remnant remains `SOURCE_OUT_OF_RANGE`.

## Decision

Add `SlipClip` to the caption allowlists in `edit_algebra.dart` and `persistent_audio.dart`. After a slip apply, call the existing `applySourceCaptionAbsolutes` helper so source-anchored cues reproject from their snapshotted absolute source time while the new source window still covers them. Do not call `followClipLocalCaptions`: clipLocal cues stay put because `timelineRange` is unchanged; absolute cues stay at author time. Do not invent a new command or change the command shape. Do not add an `includeLinks` flag.

Official persist path: import/split at 1s, add hello (`clipLocal` on the slipped left remnant) and stay (`clipLocal` on the right remnant), then `SlipClip` the left remnant by +15 source frames. `sourceRange.start` of the left remnant moves to `1/2`; timeline ranges, TimeMap, and sequence duration stay unchanged; hello stays at 0 on the left remnant; stay stays at `3/2` on the right remnant. Then linear undo/redo, archive/fork (assert by remnant times, source starts, and cue text, not pre-fork ids), and export a VTT sidecar. Preview and MP4 stay `CAPTION_RENDER_POLICY_NOT_IMPLEMENTED`. Extract is not required for this official path. A linked-AV coverage test, when used, still slips both members by the same source delta and keeps pinned sample/source ranges.

Official conflict / refusal stays whole-group, with no partial members: source head/tail shortfall (`SOURCE_OUT_OF_RANGE`), `FIELD_LOCKED`, `ANCHOR_OUT_OF_RANGE` if a source-anchored cue would leave the window, and a slip that would break transition handles. Those codes are not retargeted.

The workbench adds an official Slip control consistent with existing trim/ripple buttons: one persistent `SlipClip(_selected!, _delta())` command using the existing `edit-frames` numeric path. Tests go through the real button. This slice does not invent pointer-drag Slip as a new gesture mode.

## Consequences

I-006 stays partial: caption-aware SlipClip now has an official persist path, but roll/slide, 1000 random legal I-006 inputs, field-aware invert of Slip, and the rest of the I-006 matrix remain unfinished. I-005 stays partial. Mid-clip insert paste invert, invert of a non-last RippleDeleteClips / leave-gap DeleteClip / LiftClips, auto-close-on-move, new-track, cross-project bake, OS clipboard, source-interval crop, marker sidecar formats in this checkout, MP4 burn-in, video/caption mute/solo, `syncLock`, and the table's 0.02s off-grid offset remain out of this slice.

Production change is limited to the caption dispatch allowlists, the post-slip `applySourceCaptionAbsolutes` calls, and the official Slip workbench button. The no-caption slip algebra (`sourceRange.start += sourceDelta`, including default linked-member slip by the same delta) is unchanged. Invert production code is unchanged.
