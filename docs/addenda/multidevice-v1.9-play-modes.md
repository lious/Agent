# 多端协作玩法增量 v1.9.0：剧组与实景剧本杀单机原型

本增量在独立包 `packages/studio_play` 落地设计页「Studio 跨端协作｜剧组创作与实景剧本杀」的
**MVP A（单机 / 同进程原型）**。它不是跨端验收，不是阶段 B 局域网，也不把既有
XD-003 / XD-006 / XD-010 标成完成。持久化独立于工程库，不扩展
`packages/studio_store` 的 SQLite schema v10，也不把 v1.5 `edit_proposals`
（仍只承认 `renameProject`）扩成锁版、take 采纳、分幕或剪辑命令；未接通操作显式返回
`PLAY_UNSUPPORTED_PROPOSAL`。

## 共同定位

两种玩法共用一个会话对象：人决定做什么，设备领取被授权的工作。加入会话不等于访问整库；在线不等于可计算；收到候选不等于 writer 采纳入工程。人的创作任务（issue / claim / 提交 / 审阅 / 采纳）与设备计算 lease 分层；计算层在同进程内复用既有 `TaskLease` / `placeTask` 合同，不打开可写 peer RPC，不重试正向 RTC。

创作角色不自动获得设备管理员权限。单人可兼任，但每条审阅与决定记录写明以何角色作出。MVP 导演兼工程 writer，副导演兼场记。AI 助手只是工种工具：可起草或执行显式授权任务，不能锁版、授予角色或自批交付。

## 剧组合同（已测）

- 剧本版本不可变。导演锁定后不能暗改；非导演与助手不能锁版。改词走新版本，旧版保留；受影响未采纳任务标记待复核。
- 通告、镜头清单、sides 与 bible 从同一剧本版本派生；bible 引用 `sourceVersion`，不是第二份可漂移剧本。演员默认只见所参与场次 sides，不必看到完整剧本。
- 正式任务生命周期：issue → claim → 提交 take/draft → review → writer accept。请求不能绕过批准。取消保留历史。导演 / 副导演可全局派正式任务；编剧仅在指定场次内派工。
- 不能自批自己的交付。离线批准只记草稿意见。指定 writer 对照 play 层 revision 做 CAS 接受；过期写入拒绝，不 LWW。落后剧本版本不能自动标为已采纳。
- 撤权后不能再领任务，也不能再读取该授权下的材料。

## 剧本杀合同（已测）

- GM 用房间卡、道具标签与线索搭场；发布后冻结本局内容版本。转幕只写独立剧情事件日志，不伪装为 NLE / `edit_proposals` 命令。仅 GM 可转幕；主持端离线暂停转幕与全局公开批准，不自动接任。
- 人 / 角色 / 设备分开授权。GM 笔记本可见谜底，同账号公共屏强制观众模式，不得收到谜底或私密线索（正文、缩略图、通知、日志、搜索均不包含）。
- 玩家只领取自己的角色页。私有线索只投递指定角色；未先有明确公开动作时，公共板为空。玩家翻到最后一页不会把真相发给其他设备。
- 备用计算端只能读取已授权的公开素材；私密输入被拒绝。无合适计算设备时，可在授权主机本地执行或等待。计算结果不能推进剧情或揭晓谜底。
- 无单独同意时不能导出复盘视频；仍可保留文本复盘。本切片只落合同与许可，不进行视频编码。
