## 10G · Prompt/Skill注册、评估、AB与受控进化

| 模块 | 执行合同/发布门禁 |
| --- | --- |
| 统一注册 | 沿用8F SkillPackage/CraftSkill、PromptTemplate、EffectRegistry；RegistryPin=(id,semver,contentHash)。每个ReleaseCandidate绑定baseline/fixtureSuite/metric hash，不创建另一种可执行Skill格式。模板有显式输入Schema/能力需求/权限声明/禁用条件；模型只生成candidate包，不直接改active pin。 |
| 离线fixtures | FixtureCase(id,syntheticOrConsentedDatasetPin,inputRefs,expectedIntent/constraints,expectedGraphProperties,allowedTools,forbiddenEffects,qualityRubric,seedPolicy)。覆盖全部垂类、删改、混合输入、许可与超预算；结构/安全/事务用确定性测试，媒体感知质量需人工/VL。固定seed仅同provider/版本可参考，不保证跨版本完全复现。 |
| AB分配 | 默认仅合成/研发有权数据离线对比。真实用户内容实验须单独ResearchConsent/上传同意/费用审批，不能用购买服务同意代替。按HMAC(研究租户标识,experimentId,unitId)稳定分组，unit为项目或session避免同一任务混版本；运行中pin不变，不把userId当公开日志。 |
| 胜出标准 | 先安全/版权/审批/删除/手改保护零新增失败，再看预注册质量指标及人工盲评、成本/延迟上界、unknown率。min样本量/效应量/置信区间与分桶在ExperimentSpec先签，不事后挑有利指标；没有足够样本→inconclusive，不自动胜出。离线oracle通过不是模型质量胜出。 |
| 灰度/回滚 | candidate→evaluated→canary→active；ReleaseOwner签署fixture/许可证/兼容与指标；canary比例及回滚阈值在ReleasePolicy冻结。安全回归立即停止新run使用新pin；正在运行的计划继续旧pin或显式暂停，不热改prompt。回滚只换新Run默认pin，已生成工件保留provenance。跨App未知版本按2.0扩展规则只读/拒绝执行。 |
| Skill自进化 | 失败归因/用户明确评分→OptimizationProposal→隔离候选模板/Slot校验器/检索标签→离线评估→人工签署。不可自动增加工具权限、绕上传/支付、读取更多素材、自行部署训练或改项目。外部包按untrusted校验Schema/签名/白名单步骤；恶意包不能以“自修复”安装代码。 |
| SFT/DPO/RLHF可选实验 | 不作为首版运行依赖。数据同意/肖像声线授权/删除与用途限制→去标识与PII扫描→分离train/validation/test和同角色/项目泄漏→标注偏好chosen/rejected及依据→离线训练/评估→签署ModelProfile。SFT用审核轨迹的结构化动作，不取隐私推理链；DPO用成对偏好，RLHF另需奖励模型/采样与算力预算，不承诺必胜。 |
| 训练栈与成本 | Python离线工具链可选Transformers+TRL/PEFT适配器；版本/代码许可/底模权重与数据许可单独审批，未做训练采购不启动。vLLM只可能用于有GPU的可选服务端推理，不打包手机。训练作业必须用户数据许可、预算、资源报价和发布签署齐备；独立开发可先用模板/检索/路由优化，功能不因此缩成非生成工具。 |
