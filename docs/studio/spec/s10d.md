## 10D · 受限工具、Hook与异步结果：先权限再执行

| 阶段/对象 | 固定顺序、字段与异常 |
| --- | --- |
| ToolRegistry | ToolDescriptor(pin,inputSchemaHash,outputSchemaHash,sideEffectClass,requiresNetwork,uploadsContent,potentialSpend,resourceKind,allowedRoles,requiredCaps,maxInputBytes,timeoutPolicy,cancellationMode,idempotencyMode)。签名App配置注册；Skill/LLM只能引用，不能注册任意工具、改ns、加载源码、拼URL路径或shell。MCP只经同一ToolGateway接入，远端工具描述视untrusted，不是系统指令。 |
| 强制middleware顺序 | 输入信任标记→Schema/工具pin解析→scope与ACL→原生参数规范化→PreTool denyOnly hooks→Policy/License/Rights→报价及BudgetReservation→上传/付费/写入审批→获取资源lease→重验revision、readSet和所有epoch→持久outbox intent→执行。执行后staging→hash/Schema/QA→唯一终态receipt→候选/Proposal发布→PostTool只读观察。 |
| Hook contract | HookSpec按(event,priority,id)稳定排序；受信内置实现或签名声明式规则包，外部Skill不能放任意可执行代码。PreContext/PreTool可拒绝或缩小候选工具集合，不能改参数/提示词/权限；想改参必须生成新Proposal重走编译与审批。Stop不能自行阻止用户取消并无限续跑。 |
| 超时/fail closed | 强制安全hook必须mandatory=true、mode=denyOnly；默认内置纯规则50ms、允许配置1..5000ms，非性能承诺。超时/异常→HOOK_FAILED_CLOSED，不发请求；可选readOnlyObserve失败只记遥测告警，不把业务成功篡成失败/成功。不在hook偷偷调用付费LLM；模型质检是普通qa节点。PostTool失败不能假称撤销已发生副作用。 |
| 审批绑定 | ApprovalBinding绑定canonical执行digest：ns/逻辑call/plan pin/prompt与上传资源hash/Provider和capability pin/quote/policy/readSet/writeScope/项目revision/有效意图版本/privacy/rights/cancel epochs及到期。ApprovalBroker从受信收据库查receipt，不信模型传来的approved=true。任何项变化→APPROVAL_STALE；不能UI改了prompt仍沿用旧上传同意。 |
| 流式消息 | 沿用8A MessageEnvelope/12A HarnessMessage；RuntimeEvent追加streamId/seq/eventId/runId/turnId/itemId/attempt/type/payloadRef/privacyEpoch。TextDelta可UI节流，最终正文经可删除blob引用落库；不可将原始思考流当审计日志。工具参数仅缓存到64KiB/调用，每Iteration最多8个call，显示正文缓存≤256KiB且受maxOutputTokens约束；超限先停止流并记错误。截断、未闭合JSON、额外字段→TOOL_ARGUMENT_INVALID，最多一次不执行副作用的格式修复。 |
| tool-call成对 | Harness生成全局logicalCallId，模型callId仅作adapter映射；同一模型批次所有call先登记，再并行安全派发。每个已登记call恰有一个canonical ToolResult(success/error/denied/cancelled)，waitingApproval/submit_unknown未完成时不伪造成功继续对话。用户取消可给逻辑调用cancelled终态，之后的provider计费/产物走独立settlement事件，不能再塞第二个ToolResult。 |
| 付费outbox状态 | prepared→submitting→accepted(remoteJobId)→polling→succeeded/failed/cancelRequested/settled；网络断在提交点→submit_unknown。先持久逻辑call/输入hash/幂等键/预约，再提交。只有provider明确支持幂等提交且key语义已验证才能原key安全重试；否则查remoteId或按key查询，不支持查询则needsReview/人工账单核对，阻止再次生成。 |
| 回调/轮询/晚到 | 同时以providerEventId inbox去重和logicalCallId终态receipt去重；不同eventId同一Job不得再入库另一份Candidate或再扣费。相同ID异hash→IMMUTABLE_ID_CONFLICT并告警；同Job账单金额冲突另开账务差异，不静默覆盖。先验证签名/tenant/job绑定，再单事务结算/收据/outbox。取消或删除后已发生费用仍结算，但stale epoch内容不得挂回当前工程。 |
| 取消与释放 | CancelToken下传provider/FFmpeg/native推理；取消已收敛前不销毁仍被GPU/编码器引用的buffer。finally释放资源lease/临时tokenizer/KV；产物staging由引用计数和GC宽限处理；保留对账所需非正文元数据。可重启的resumeToken包含输入/模型/运行时hash，不含跨模型KV或账号凭据。 |
