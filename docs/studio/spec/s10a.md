## 10A · 当前有效意图、删除与压缩：摘要不是事实数据库

会话有六份不同真相：可清除的消息正文、只记发生过什么的事件头、当前有效意图/约束、已确认决策与工件、Project Revision、供模型使用的可重建上下文。Project没有因聊天被删而自动回滚；历史也不能因为fork/resume或旧摘要被加载而让已撤销内容再次生效。本节替换旧“保留所有原事件正文就能保证正确”的假设。

| 用户实际动作 | 语义、传播与恢复 |
| --- | --- |
| “改成… / 不要以前那版…” | 先解析明确实体/字段和作用域，预览IntentDelta；确定的标量变化可直接显示可撤销chip。Supersede(i1→i2)保旧事件头但i1不再入上下文，依赖旧值的prompt/提案stale。只否定当前值而没给新值用Retract，槽位变unset，要求补信息，不能回退到更早被否定值。模糊“删掉她/那个”在多个候选时显示指代选择，不删素材。 |
| “不用这条内容” | ExcludeSourceUse针对明确scope撤销输入使用；正文可仍供用户在UI查看，但不得再进该scope模型、FTS/RAG、摘要或自动推断。依赖它且没有其他有效证据的意图/决策转stale或retracted。需要保留某已确认事实时用户显式重新确认为新的独立输入，不能悄悄通过摘要绕过。 |
| 删消息 / 软删除会话 / 永久清除 | Trash隐藏并排除新上下文，保留期到期前可恢复正文；Purge实际清本地消息正文/附件消息副本、摘要、FTS/embedding、语义缓存、诊断导出队列以及受影响派生文本。默认撤销solely-sourced意图，不让old summary复活。已接受Project镜头/字幕不会默默被回滚：预览列出这些独立副本，用户可明确保留当前工程成果，或选择“连派生也清除”。后者需单独预览/批准不可逆工程历史裁剪。 |
| 删镜头 vs 删源文件 | 删除镜头=RemoveShot/Clip的NLE内容命令，保留已生成源与计费记录；删除源文件=明确FileToken及全部1:N引用影响清单后确认，阻止依赖使用、工作区AccessRecord置revoked（不向封闭Asset.status塞policyBlocked），工程Asset仅用既有quarantined/missing，不能把“删这一句对话”解释成删文件。相同blob仍被其他授权版本引用时不得随便unlink；是否连全部副本/派生删除由用户选。 |
| Undo / Fork / Resume / 导入旧归档 | 普通编辑Undo产生新revision；Intent撤销以新事件恢复明确值；永久隐私清除没有通用Undo。fork在父watermark冻结内容继承，但每次读取都叠加workspace全局PrivacyRevocationSet；旧分支、旧索引、旧快照不能越过删除屏障。导入外部旧归档若含撤销source指纹/ID，在本机继续阻止，重新导入使用需用户显式重新授权；未知外部副本不宣称能隔空擦除。 |
| 并发分支/作用域变化 | 相同字段并发不同值产生ConflictGroup，暂停依赖生成；无冲突的不同字段可显式cherry-pick。删除/换主角发生于运行中：未提交的付费请求审批失效；已提交请求请求cancel并标历史scope，不能保证停费。完成晚到结果进quarantined，只有当前权限/版本重新验收后可选用，不自动拼进时间线。 |

// 精确压缩算法（逻辑步骤，非已部署数据库实现）
compileContext(branch,scope,agent,model):
  tx read consistent {head H,Project revision R,privacyEpoch P,grantEpochs G}
  load latest snapshot whose lineage/schema can be read
  if snapshot.P != P or any body/source grant revoked: discard snapshot entirely
  reduce snapshot.effectiveState + ordered eligible events (watermark,H] -> current ledger
  overlay workspace privacy/source denylist before loading any body
  resolve scope/constraints + currentProject locks; conflicts => clarification, not generation
  revalidate every summary claim.supports and dependency selector
  drop unsupported/retracted/superseded/purged claims; do not replay retired value text
  compile current intent/decisions deterministically, not from free prose summary
  fetch only eligible observations/artifacts/RAG; include citations/coverage gaps/conflicts
  recent handoff is typed current projection, NOT blindly last N raw chat messages
  count actual tokenizer tokens including media/tool schemas; reserve output+safety
  if mandatory blocks > B: CONTEXT_TOO_SMALL; offer narrower scope, never drop permissions/locks
  select evidence chunks within B; emit omittedIds/nextCursor
  recheck H/R/P/G and cancelEpoch; change => CONTEXT_STALE, bounded rebuild

compactInBackground():
  tx freeze {H,R,P,G,activeIntentDigest D,eligibleBodyIds}; pin allowed immutable artifacts
  outside tx: deterministic state checkpoint + bounded optional summarizer for observations
  each summary claim must cite allowed evidence; no unsupported free-text“current constraint”
  tx CAS check currentHead==H && revision==R && epochs==P/G && digest==D
  if changed: reject stale draft, release pins; at most 2 retries, then deterministic facts+tail
  else atomically save snapshot + snapshotPublished event/receipt; commit
// 已发布snapshot的watermark之后仍可有tail；读取时先最新denylist，再有序reduce tail。
// 新head不会让旧摘要里的主角/时长恢复；PrivacyEpoch变了则整个旧摘要禁读，需重建。
// 压缩调用也需要输入许可/预算；绝不为了压缩自动把本地长会话发云。

privacyDelete(approvedPlan):
  begin immediate
  CAS privacyEpoch; add source/turn tombstones; revoke grants; increment privacyEpoch
  invalidate snapshots/index views/approvals and dependent active intents
  set affected runs noDispatch + increment cancelEpoch; append deletion header/outbox
  commit  // 先阻访问；所有读取、提交、缓存命中均检查epoch，无等待后台GC窗口
  cancel remote jobs where supported; reconcile unknown submit once, never blind重复收费
  purge local body/summary/embedding/cache/diagnostic copies by dependency closure
  checkpoint/index rebuild/WAL cleanup and unpin unreachable blobs; retry cleanup idempotently
  publish PrivacyReport; remote failure/notSupported保持可见，不能标“已全网删除”
// API不支持delete则记录notSupported；已上传/已付费不可逆，训练/备份保留不作保证。
// 本机删除提供应用级不可再访问和可验证清单；SSD/WAL/系统备份的取证级擦除不保证。
// 崩溃点：epoch已提交但purge未完→重启先装denylist再读正文，重放outbox继续清理。
// 旧归档/用户手动复制的外部文件不在本机删除闭包可控范围，报告明确列出。

ApprovalBinding = H(providerId+modelId+resolvedVersion+profileVersion+region+dataPolicyHash,
  finalCompiledPrompt+providerParams+templateVersion+capabilityHash,
  exactAssetVersionsAndSelections+uploadPlanHash+rightsSnapshot,
  currentIntentSliceDigest+projectRevision+scope+lockedPaths,
  quoteHash+budgetReservationId+privacyEpoch+sourceUseEpochs+cancelEpoch)
// 编辑prompt/替换图/改时长/改主角/revision更新：dispatch前重算，不等则APPROVAL_STALE。
// 已发外部任务：旧批准仅证明当时授权；新状态不使结果自动合格，也不承诺可退费。
// complete -> candidate.ready/quarantined + receipt，不直接commit工程；

工程/会话/删除边界进一步闭合：默认.studioproj不包含消息、RAG、临时分析；选择“保留制作依据”才写ProductionManifest与选定证据正文，manifest对blob闭包负责。选择导出会话时，沿用sessionArchive映射projectRevision，但新归档仅含当前许可的消息/意图及删除头，先应用revocations，不把被purge正文夹进压缩包。撤销批准、密钥、运行lease一律不导出。源数据在已另存工程/备份/provider中的副本必须在删除预览单列，不能把“删聊天”宣传成它们也被擦除。

若用户明确要求连已采纳工程里的敏感prompt也永久清除：PrivacyErasePlan需列出GenerationRecord.promptText/negativePrompt、stage正文、Undo/旧snapshot和导出缓存的全部副本；经不可逆确认后生成去敏新revision（promptText/negativePrompt允许null），清除旧可达正文及历史恢复点并设置privacy barrier。promptHash若也需移除，写新去敏标记digest并在已声明studio.privacy.v1扩展列redactedDigestPaths，明确不再是原prompt指纹；不伪装为原始溯源。旧归档外部副本/远端保留不在保证范围。含该信息的成片像素不能靠删文本去除：须阻止使用对应候选并让用户删除/替换，不能承诺无损“忘掉画里的人”。普通聊天删除不隐式执行这一破坏性工程操作。studio.privacy.v1合同为schemaVersion、barrierRevision、redactedDigestPaths、blockedAssetRefs；只有执行这种工程清除才声明requiredFeatures=studio.privacy.erase.v1。缺此能力的App可只读查看已去敏元数据，但禁止生成/上传/导出及访问被撤销媒体，不能把该扩展当普通advisory忽略。
