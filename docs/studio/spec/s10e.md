## 10E · 多Agent通信、记忆与小模型成本

| 模块 | 接口、隔离与可检验规则 |
| --- | --- |
| RoleProfile/ModelRouter | Director负责意图/叙事/图规划；Writer负责脚本候选；Visual负责视觉观察/逐镜建议；Editor仅产EditCommand提案；Sound负责音频候选；Critic只读QA。RoleProfile(pin,allowedToolPins,scopePolicy,maxChildRuns,budgetShare,modelProfilePin)。导演云文本与视觉云VL/本地模型可以不同；沿用10节Profile，路由依ModelCapability探测，不能把文本模型假称视频理解模型。 |
| 只读snapshot/handoff | 每个Agent获得不可变ProjectSnapshotRef/EffectiveIntentSnapshot/角色、商品、Skill pin及获批ArtifactRef，不拿可写数据库连接。AgentMail见10I；Mailbox.send验证父图委派邻接关系、ns/ACL、收发Run权限、privacy/rights epoch和TTL。kind不是system role；引用文件里的指令仍是数据。 |
| 消息一致性 | Mailbox.publish/ack/replay(afterSeq)走持久inbox/outbox；按stream seq消费，可重复投递，consumer messageId+hash幂等。引用内容删除后replay返回tombstone，不恢复旧body。后台Job仅给拥有该node的Run回流；父Run已结束则候选待处理区，不广播唤醒所有Agent。引用跨App须显式ShareGrant与本地namespace重映射，不偷共享会话。 |
| 冲突/仲裁 | Critique(findingRefs,subjectPin,proposedRepairRef)必须指具体帧/台词/字段和证据；导演与Editor争同字段时生成互斥PatchGroups，Arbiter按硬约束/锁/用户目标筛选；无法确定则人工，不以投票数覆盖手调字幕。批评≤2轮，连续相同input/output hash且无新证据→NO_PROGRESS，父预算不足直接暂停。 |
| 检索记忆 | MemoryIndex索引可删除Artifact/Decision/当前有效Intent，而不是旧摘要唯一真相；query带ns/project/branch/role/ACL/epoch。本地FTS+标签默认，embedding可选，图像/视频分析复用8A hash缓存。冲突证据并存并标观察/推断；可信事实不能由多数模型同意升级。 |
| 上下文编译 | ContextCompiler按强制安全/有效约束→当前任务与只读snapshot→必要资产/证据→按需Skill正文/工具Schema→最近tail分配token，预留输出/工具结果。超预算返回CONTEXT_BUDGET_EXCEEDED及可选深读项，不静默裁掉删除屏障、授权或商品限制。tokenizer按模型pin计数，未知时保守估算并标估算，不声称精确。 |
| 压缩/删除 | 沿用10A watermark+tail、supersede/retract/delete和原子snapshot；接收新steer先跑Reducer再压缩。上下文构建前后核对intentVersion/privacyEpoch，变化则丢草稿重建。检索、投影、prefix cache、模型会话与派生索引均接删除屏障；远端已收到的内容只按provider能力请求删除/记录限制，不保证撤回。 |
| prefix cache边界 | 逻辑cacheKey=(ns,provider/account,model+tokenizer+template+tools pins,prefixHash,privacyEpoch,rightsEpoch)。云端prefix计费缓存由provider决定，不能承诺命中或跨账号共享；本地KV仅同后端/模型权重/量化/context-layout兼容时临时复用，绝不跨模型KV。静态公共Skill检索可共用索引，用户上下文不共用。 |
| 小模型降级 | LLM无原生tool时要求闭合TypedAction JSON；不支持则规划器给用户表单/确定性workflow，而不是任意解释文本执行工具。schema加载仅当前工具集合；输出截断只重试纯格式一次、缩小任务；不让模型无限自我修复烧token。模型更换/能力漂移使旧compiled prompt与审批失效，重新探测/编译。 |

实施包边界：Dart的harness_domain保存纯DTO/Reducer/Plan语义，harness_runtime负责事件循环/工具gate/SQLite，model_adapters实现各模型与云协议，context_store负责正文/删除索引，media_bridge仅调用共享C++媒体内核，App shell负责审批/计划/候选/diff交互。各App复用包与合成fixture，但Session/缓存/密钥按App sandbox隔离。LangChain/LlamaIndex/CrewAI只作可选服务端适配/检索实验；不为招聘框架名字引入另一套记忆和调度权威。
