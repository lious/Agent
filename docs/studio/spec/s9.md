## 9 · 会话管理不是聊天列表：作用域、分支与编辑边界

借鉴公开机制：Claude Code文档明确本地连续保存、命名/resume/branch与导出；Codex公开CLI提供saved chat resume、权限控制和模型选择。这里只参考可见机制；不声称复制其内部压缩算法、DeepSeek内部Harness或能把IDE文件回滚直接等价为媒体工程回滚。本产品把会话分支与工程revision分开建模。

```text
Session {id,namespace,projectId,title,scope:{kind:project|shot|selection,
 sequenceId?,shotIds[],clipIds[],frozenAtRevision}, activeBranchId,
 status:active|archived|trashed,createdAt,updatedAt,deletedAt?,recordVersion}
Branch {id,sessionId,name,parentBranchId?,forkEventSeq?,headEventSeq,
 baseTimelineRevision,workingTimelineRevision?,status,recordVersion}
Turn {id,branchId,userContentRef,attachments:AttachmentRef[],createdAt}
// 第8A节ContentPart[]为有序消息正文；userContentRef指向该版本的MessageEnvelope。
// 第10A节事件元数据与可清除正文分离；恢复/分支不得绕过来源撤销。
Run {id,branchId,turnId,parentRunId?,agentProfileId,modelProfileId,contextSnapshotId,
 status,leaseOwner?,fencingEpoch,leaseUntil,cancelEpoch,attempt,
 dependencyRunIds[],budgetReservationId,startedAt?,endedAt?,error?}
ShotCandidate {id,shotId,shotVersion,parentCandidateId?,assetRef,generationRecordId,
 state:processing|ready|selected|rejected|quarantined,createdByRunId,qualityNotes[]}
Proposal {id,branchId,runId,baseTimelineRevision,patchGroups[],readSet,writeSet,
 lockedFieldSnapshot,previewRef,hash,state:draft|ready|partiallyAccepted|applied|stale|rejected}
PatchGroup {id,label,operations[],dependsOnGroupIds[],risk,acceptedCommandId?}
TimelineRevision {projectId,revision,parentRevision,snapshotHash,commandId,actorId}
// Session—Branch—Turn—Run 是会话因果；Project—Revision是内容历史。
// 一条Branch可以生成N个Proposal，接受前不拥有正式工程写权限。
// “会话分支合并”不是文本合并整个工程，只能显式cherry-pick已验证PatchGroup。
```

| 屏幕/状态 | 用户动作→命令→持久事件 | 反馈、撤销与边界 |
| --- | --- | --- |
| 项目库 | NewProject(用途)/OpenPackage→project.created/project.opened；项目卡显示封面、时长、缺媒体、最后已记录revision。 | 最近项目和最近会话分开；外链缺失不阻止查看工程结构。删除进回收站，可30天恢复；永久清除二次确认。 |
| 项目会话侧栏 | NewSession(scope,title)、RenameSession、ArchiveSession、SearchSessions(query)、SelectSession。事件session.created/renamed/archived；搜索本地FTS title/用户正文/摘要，敏感内容按保留策略。 | 切换不取消运行、不重置播放头；运行badge保持。新会话默认项目scope，选择片段发起时显示“仅这2片段”，clip删除后scope invalid，不自动扩到全项目。 |
| 会话详情/branch picker | ForkBranch(atEventSeq,name)→branch.forked；ResumeBranch→恢复事件投影，必要时reconcile未终态job，不重发工具。 | 分支继承父前缀≤fork点，原分支不变；新分支默认读取当前工程或用户指定snapshot，必须明确显示哪一个。fork不复制媒体Blob/KV cache/旧上传批准。 |
| 运行卡/审批卡 | SubmitTurn→turn.created/run.queued；PauseRun请求safe point；CancelRun→run.cancelRequested；审批ApprovePlan(proposalHash,uploadPlanHash,quoteHash)→approval.granted。 | 显示Agent/模型/当前步骤、tokens/金额估计、已发外部任务、可取消性；用户离开屏幕不等于取消。付费/上传/删除从不因“自动编辑”总开关免审批。 |
| 建议预览/diff | OpenProposal显示新增/删除/移动片段、字幕文本diff、上传/收费清单；AcceptGroups(groupIds)→校验依赖闭包→command.committed；Reject→proposal.rejected。 | 默认候选沙箱，timeline幽灵层不是真提交。可全收/逐组接受；字幕修字可单独接受，但引用新Clip的效果不能先于Clip插入。拒绝不删原件或已付费候选。 |
| 手动编辑与锁定 | Trim、EditCaption、LockFields等走同CommandCoordinator；事件document.changed，同时给后台proposal发stale或revalidationNeeded。 | 用户手动修改不能被后台生成覆盖。字段锁如clip.source/clip.timelineRange/caption.text独立；“只改字幕，不改原音”转成writeSet仅caption.*，工具/验证器双重拒绝audio写。 |
| 分支挑选应用 | CherryPickProposal(fromBranch,groupIds,targetRevision)→在当前snapshot重新plan/预览→CAS提交。 | 无通用merge按钮谎称自动融合；相同Clip同时trim/换take冲突展示两版，用户选择。仅改不同Caption.text可字段级重基，必须记录readSet验证。 |
| 归档/删除/恢复 | ArchiveSession无取消；TrashSession提示是否同时取消其runs→session.trashed；RestoreSession→active；Purge需独立确认与数据范围。 | 删除聊天不删除时间线已引用的素材；project删除与session删除不同。会话恢复不会复活已撤销审批/已删除来源/凭据。 |
| 跨设备/跨App | P1显式工程/会话归档导入；P2 SyncEnvelope{deviceId,appId,streamId,eventId,parentIds,hash}，只有已开启同步scope才上传。 | 并发branch产生分叉，工程保持单写lease+revision CAS，不用last-write-wins。跨App须用户导出/导入，批准和secret绝不迁移；没有同步服务时明确仅本机。 |

```text
// Proposal提交原子性（packages/studio_document/commit_coordinator.dart）
accept(groups, expectedRevision):
  begin immediate transaction
  assert proposal.scope == authenticatedScope
  assert hash(proposal) == approvedHash
  assert dependencyClosure(groups) == groups + alreadyAcceptedDependencies
  assert currentRevision == expectedRevision
  assert entityVersionsAndReadFieldsMatch(readSet)
  assert no writePath intersects lockedFields or forbiddenWriteSet
  apply groups with EditAlgebra; validate document/source limits
  append Command + Revision + document.changed + receipt
  mark accepted group IDs IN WORKSPACE RECEIPT; increment revision once
  append ProposalAccepted projection-outbox intent
  commit workspace transaction
  // Session DB的accepted投影按commit receipt幂等更新，不伪称跨DB同时commit。
// revision不符：只允许显式RebaseProposal重新计算read/write并重新展示，不能盲重试。
// generation完成只发布candidate.ready，不执行accept。
// cancel与commit同一epoch比较：commit先赢→ALREADY_COMMITTED；cancel先赢→不能commit。
```

粒度与能力边界：LLM能改Brief/镜头建议、提出剪辑参数、调用受审工具生产候选；不能直接写SQL/工程JSON/任意源文件，不能执行下载到的prompt脚本。用户可确定性改clip边界/字幕/音量/位置/颜色/关键帧；生成内容中的人脸、物体、口型需新生成/专用编辑模型，不能伪装成无损可逆参数。候选删除与不可逆云删除单独确认。
