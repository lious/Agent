## 8 · 真正的视频生成：用途Brief、prompt编译和候选入NLE

参考的是公开工作方式，不猜产品内部实现：Runway公开的Gen-4流程为选择模型、首帧/文本、时长/比例/seed、生成、会话中滚动候选、Assets复用/用当前帧继续；其旧代指南强调I2V描述运动、避免negative。Firefly公开流程将生成媒体拖入多轨时间线，首尾帧与参考能力存在互斥。由此得出本产品“生成候选”和“确定性编辑”分区，不照抄品牌UI，也不把旧代Gen-4能力当当前所有模型规则。

模板UI：新项目先选用途卡片→表单只显示该用途字段→镜头表格可改叙事功能/时长/摄影意图→每镜“高级prompt”展示编译后完整正文和provider参数→支持用户编辑/恢复模板/比较版本→生成确认页显示上传清单、模型、每镜生成时长、候选数、估价与上限。duration/aspect/seed是API参数，不仅写在prompt里。画幅、字幕、Logo、配乐切点、总时长属于编辑器强约束；“更电影感、主体一致、笑容自然”属于模型建议，必须预览挑选。

| 类/方法 | 执行细节、异常与成本 |

| UploadApproval / PrivacyGate | 本地读取/本地模型/云推理三个权限独立；生成前列出上传图片/音频/抽帧、目的provider/region/保存政策与截止。只上传批准的最小裁剪/降采样副本，保reference→upload hash映射。用户拒绝则无HTTP，回到离线剪辑；模型文本无法授权。 |
| GenerationGateway.submit(requestId,inputHash,approval,quote) | 凭据只在后端secret store或用户明确BYOK的设备安全存储，不能打包进App。后端校验tenant/project/receipt/budget/上传批准；outbox durable记录后提交。网路超时且可能受理→acceptanceUnknown，不自动重POST；本地幂等不能冒充provider端到端幂等。没有远端查重能力则人工确认后才新请求并提示可能重复计费。 |
