## 6 · 已定主线：FFmpeg＋共享编辑内核＋各端硬件适配

Dart持有ProjectDocument/EditCommand/事务、UI及独立Session/Context/Harness；C++20只持有不可变RenderRecipe、媒体执行图和运行状态，不回写第二份工程。平台API不是被FFmpeg排斥，而是通过硬件wrapper或受控PlatformCodecAdapter接入共享底座。商业SDK仅保留成本/能力比较，不作为当前主线。

| 层 | 主选型/职责 | 为何不是FFmpeg包办 |
| --- | --- | --- |
| demux / probe | 所有原生端统一libavformat＋自定义受权AVIO；avformat_find_stream_info/probe生成StreamInfo/PTS索引。 | FFmpeg内不自动联网、不接受LLM任意路径；FileToken绑定宿主namespace。Apple/Android/Windows不再各自使用另一套容器/edit-list解释。 |
| decode / encode | 优先libavcodec硬件wrapper/hwcontext：VideoToolbox、MediaCodec、D3D11VA/MF、VAAPI；软件解码也用libavcodec。 | 硬件wrapper不能覆盖的GPU输入路径由PlatformCodecAdapter实现；输出仍转EncodedPacket交libavformat。FFmpeg默认没有可任意使用的通用软件H264 encoder，不能把解码fallback偷换成编码fallback。 |
| filter / composite | 共享C++ RenderGraph/EffectRegistry＋CPU参考＋Metal/GLES/D3D11/GL后端；libswscale做显式像素格式/矩阵转换。libavfilter只按受审注册表启用。 | 预览与导出均由同一语义图编译，不能导出时另拼drawtext/overlay命令串。libswscale不自动解决HDR；字幕整形/glyph与字体hash跨端共享，不依赖各端系统默认排版。 |
| timeline scheduling | 自有有理时间、source map、clip依赖、精准seek、音频主时钟。 | FFmpeg命令行滤镜串不保存用户可编辑工程/undo/审批。 |
| audio mix | 各原生端统一libavcodec解音频→libswresample转48k Float32及声道矩阵→共享总线DSP；导出用FFmpeg原生AAC-LC encoder。 | 预览音频设备由CoreAudio/AAudio/WASAPI/PipeWire等AudioSink适配；swresample的delay要flush，不能用提交到ring的sample数代替实际播放时钟。 |
| render / mux | 共享RenderRecipe→CodecAdapter→libavformat MP4；av_packet_rescale_ts后按DTS交错写包，drain→trailer→验证→发布。 | 不从preview纹理截图导出。P1所有编辑输出重新渲染编码，smart render/混合stream-copy禁用，避免keyframe/extradata/时间基不一致。 |

| 平台 | 容器/codec/GPU/桥接 | 拷贝和能力边界 |
| --- | --- | --- |
| iOS / macOS | libavformat→H264/HEVC decoder＋VideoToolbox hwaccel→AV_PIX_FMT_VIDEOTOOLBOX/CVPixelBuffer→Metal合成→encoder pool CVPixelBuffer→h264_videotoolbox→libavformat。 | 同设备、IOSurface可映射且格式匹配才可免CPU回读，GPU颜色/缩放/输出拷贝仍存在。AVFrame引用持有pixelbuffer直到GPU/encoder消费完成；不把借用的CV/CF指针重复release。AVAssetReader/Writer不再是默认主路。 |
| Android | libavformat→h264_mediacodec/HEVC wrapper→AVMediaCodecBuffer→SurfaceTexture/OES→稳定FBO；合成→encoder EGLSurface。Kotlin桥Surface/生命周期，循环在native串行队列。 | n9.1 encoder虽有Surface分支，不能把普通FBO伪装成解码buffer传send_frame。P1 GPU输出用AndroidSurfaceEncoderAdapter直接接NDK/Java MediaCodec，CSD/packet归一后仍由libavformat mux；受测ByteBuffer路径可用h264_mediacodec。JNI Surface与ANativeWindow所有权分开；AHardwareBuffer不是通用FFmpeg MediaCodec帧。 |
| Windows | libavformat→decoder＋D3D11VA→D3D11 texture+arraySlice→D3D11合成/NV12输出池→h264_mf→libavformat；COM专属MTA worker。 | 本轮n9.1 mfenc.c已核对存在D3D11输入和DXGI device manager，不再误说一定CPU上传。仍要求同device、可采样/可编码格式和有效hw_frames_ctx；420_OPAQUE不能默认transfer。MF不接受本机NV12纹理时改CPU NV12输入并标copy，不保证零拷贝。 |
| Linux原生 | 同一FFmpeg/C++内核；首个验证目标为Ubuntu 24.04 LTS x86_64，VAAPI hwcontext→DRM_PRIME/EGL/GL合成→h264_vaapi；音频PipeWire适配，ALSA兼容回退。 | 这是目标配置而非已支持声明。DMABUF plane/modifier及同步双方匹配才可直接import；不匹配则CPU下载/软件解码＋上传VAAPI。NVENC/QSV是后续受审profile，不把“Linux”视为所有GPU都可编码。 |
| Web桌面 | 单独WebMediaPort：demux/mux JS模块+WebCodecs；Worker进行decode/encode，OffscreenCanvas/WebGL2合成；WebGPU可选。 | WebCodecs不定义任何必备codec且不负责容器。VideoEncoder/AudioEncoder.isConfigSupported后实测；VideoFrame/AudioData及时close；OPFS/IndexedDB容量/驱逐、跨origin隔离和后台限流单列。JS demux/mux库版本/许可仍要构建前定向审计；不默认使用ffmpeg.wasm替代WebCodecs：WASM内存/拷贝、线程隔离header与codec许可都需独立profile，不能直接复用native硬件AVFrame。 |
| Web移动 | 会话/生成/图片优先，受控短片预览可能力开放。 | 不能声称与native全等：内存、codec、文件和后台都有不同限制；不支持的导出显示明确门禁，不偷偷转云。 |

本轮打开官方download页显示当前稳定版9.1（2026-11-20发布）；这是调研日期所见，不是项目已完成升级构建。项目锁具体tarball/hash与配置，安全修复按SBOM追踪。默认FFmpeg大部分LGPL-2.1+；--enable-gpl会改变组合许可，--enable-nonfree不能当可分发商业构建。x264/x265、外部滤镜/音频库分别审计。专利、商店规则和代码版权是三件事。

发布方案现在包括移动端FFmpeg：桌面/Android优先受控shared libraries，iOS以静态库集成到自有XCFramework作为待审发布形态；两者都必须交付对应源码、构建配置/补丁与许可证。LGPL静态链接不是一概禁止或一概免责，必须形成可执行的重链接材料与EULA/签名分发审查方案；许可审查缺口进入1C风险清单不阻本项目构建/打包；真实平台拒绝、完整性/安全/能力未过仍阻止相应操作，不暗中退回“移动端不用FFmpeg”。GPL/nonfree的分发限制仍如实记事实/义务；缺商业许可按1C默认风险放行，不作为项目自身发布硬阻断。具体每App分发、codec专利、商店实际审核与安全能力分开。

FFmpegKit已退休，不能把旧pub/CocoaPods二进制作为默认。官方页面本轮另提示FFmpegKitNext续作且source-only；是否使用仍需单独审构建/版本/许可证，不因同作者就自动信任。主线不依赖任何未维护二进制。商业SDK选择门槛：合同覆盖各端/多App/离线/导出与终止后读取；10个核心NLE fixture无语义丢失；工程可移出；codec与专利责任书面明确；总成本报价可承担。未过这些门槛不签、不谎称“商用成熟”。

低预算实施仍沿同一FFmpeg主线，先打通受控H264/AAC竖切再扩格式/平台，不缩减为贴纸或仅拼已有素材。商业SDK仅作为成本/进度备选，若未来替换必须显式ADR、通过项目语义移出/往返门禁；不能悄然存两套时间线。使用FFmpeg底座并不自动获得成熟NLE、实时4K或商业授权保证。
