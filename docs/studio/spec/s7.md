| 主题 | 实现决定/异常行为 |
| --- | --- |
| 线程归属 | UI线程只输入/绘制；document isolate单写者；IO pool做文件/hash；每路codec串行队列；audio callback无分配/锁/DB；render queue提交GPU；export worker处理背压；模型worker不占用UI。平台回调先入队再转domain事件。全局ResourceArbiter给codec session/GPU bytes/LLM KV/ASR发租约。 |
| 精准seek | 目标t经Clip timeMap→source PTS；索引定位前一个关键帧，flush decoder，解码并按PTS排序，丢弃不覆盖目标t的帧，返回覆盖帧。快速scrub可关键帧近似但标“预览低精度”，停手后精确seek。每次seekGeneration递增，晚帧/旧recipe禁止显示；取消只影响本次consumer不释放仍在GPU的buffer。 |
| 播放与drop-frame | 音频已消费sample为master clock，视频选择覆盖clock时间的帧。晚于显示deadline超过一输出帧则只丢显示，继续必要参考帧解码；音频不为追视频任意删sample。无音频用monotonic clock+明确暂停累计；seek重置音频ring和clock anchor。 |
| 背压 | 每路已解码ready队列最多3帧，不是把硬件DPB/参考帧池也设为3；池预算=codecMin＋ready＋renderInFlight＋encoderRetention＋margin。预览mailbox=1，音频ring目标100ms/上限300ms为待测初值。导出不丢帧；encoder不ready就停止上游pull；队列同时限count/bytes，多个转场源预先申请租约。 |
| 模型竞争 | 预览优先于可延迟本地推理；本地heavy lease默认1（LLM/ASR/扩散互斥），cloudSlot默认2但先有预算。导出前若无法共存请求卸载本地LLM，确认native safe-point后才free KV；模型OOM可降context/分段后再提议，不偷偷改云模型上传。 |
| 取消与完成竞态 | job cancelEpoch CAS；实际GPU/codec不能立即中断则进入draining，完成回调只归还资源，不发已取消job的可应用结果。文件先.partial，cancel后删除临时输出；已commit完成的导出可留用户文件，取消返回ALREADY_COMMITTED而非谎报撤销。 |
| 硬件失败fallback | decode configure/import失败→一次受测同设备重建或libavcodec软件解码；不能transfer的opaque帧从压缩源重新seek软件解码，不强行map。encode先释放预览资源再重建一次，仍失败仅试满足同preset的系统软件encoder/已审libopenh264；不存在或profile不符返回ENCODER_UNAVAILABLE。降720p/改profile须确认，新建preset/recipe；永不自动带入x264/x265。 |
| 资源释放 | begin_close停止新请求→cancel/drain→Presenter解除texture订阅→等待GPU/encoder消费者归还lease→关闭codec/AVIO→释放设备context；wait_close超时返回PENDING_LEASES，不能先free造成UAF。设备丢失走error fence回收，不无限等永远不会完成的GPU。跨FFI错误保留domain/code/stage/nativeCode/retriable/correlationId，不输出凭据/签名URL。 |

明确首版输入/交付路径：接受MP4/MOV内H.264 High/Main/Baseline、8bit 4:2:0、progressive、≤3840×2160/60（实际受设备能力收窄）＋AAC-LC stereo；iPhone HEVC Main/Main10属于能力探测后归一输入，不保证每端可用。例：1080×1920 H264 30fps、AAC48k文件→libavformat probe/edit-list/PTS索引→libavcodec硬件/软件decode→共享linear709合成三轨/文字→Rec709 limited NV12→硬件CodecAdapter编码H264 High@4.1；音频用libavcodec＋swresample＋总线DSP＋FFmpeg AAC-LC→libavformat MP4/faststart→重开验证。

```text
ExportPreset social-1080p30-sdr@1 {
 container:mp4, video:h264, profile:high, level:4.1,
 width:1080,height:1920,fps:30/1,pixelFormat:yuv420p,
 bitDepth:8,bitrateTarget:12000000,gopFrames:60,maxBFrames:0,
 audio:aac-lc,sampleRate:48000,channels:2,bitrate:192000,
 color:bt709/limited, alpha:flattenToSequenceBackground,
 captions:burnIn|sidecarSrt, faststart:true
}
// 15秒输出450帧，音频可听内容720000sample；padding/edit metadata单独处理。
// pixelFormat:yuv420p描述编码色度采样，硬件输入可为NV12/CVPixelBuffer，不要求CPU planar拷贝。
// P1输出禁B帧；输入仍可有B帧。原生encoder缺DTS时仅在no-reorder合同及packet校验成立后DTS=PTS。
// 导出冻结rev与source版本；中途用户编辑新rev不改变本job。
// H264 High10/4:2:2/交错/损坏PTS等不在本preset输入承诺：
// 可解码则显式去交错/降bitdepth/归一，不能解码则UNSUPPORTED_PROFILE并给信息。
// 验证：容器可重开、帧数/时长、音视频端点、首尾图像、无残缺partial；最后原子发布。
```

FFmpeg现为共享主路径，所有FFmpeg/平台codec都实现同一CodecAdapter合同；不另拼一条与预览不同的滤镜图。离线export遇后台中断或编码设备丢失，P1从冻结snapshot/recipe开新attempt和新.partial从头渲染，不能把不同encoder extradata/GOP的packet接到旧MP4尾部。重试不重新调用付费生成，不回滚用户之后的编辑。
